# 资源推动 Agent 配置管理使用手册

## 1. 适用范围

本手册适用于当前固定结构的资源推动 Agent。Node Registry、业务流程、工具权限边界和 Loop 逻辑由代码管理；后台用于管理模型连接、可选模型、节点模型绑定、Prompt 工作稿和稳定版本。

当前不支持创建多个 Agent，也不支持在后台修改节点拓扑、Loop 参数或运行逻辑。

## 2. 启动前配置

实际运行配置写在项目根目录的 `.env`，不要把真实密钥写入 `.env.example`。

```dotenv
AGENT_ADMIN_ENABLED=true
AUTH_ENABLED=true
AGENT_SECRET_KEY=<固定的 Fernet 密钥>
AGENT_TRUSTED_MODEL_HOSTS=vftsub.vf-tech.cn
```

首次需要生成 `AGENT_SECRET_KEY` 时执行：

```powershell
docker compose exec -T backend python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

将生成结果配置到 `.env` 后重新创建后端和 Worker：

```powershell
docker compose up -d --force-recreate backend worker
```

`AGENT_SECRET_KEY` 用于加密数据库中的 API Key。已有密钥写入数据库后不要随意更换，否则原有 Secret 将无法解密。

如果模型域名解析到内网或代理的 Fake IP，只放行确定可信的域名：

```dotenv
AGENT_TRUSTED_MODEL_HOSTS=model.example.com,another-model.example.com
```

不建议使用 `AGENT_ALLOW_PRIVATE_MODEL_URLS=true`，因为它会放开所有内网模型地址。

## 3. 登录和管理后台

启动服务：

```powershell
docker compose up -d --build
```

访问地址：

- 业务页面：`http://localhost:3000`
- 管理后台：`http://localhost:3000/admin`
- 后端 API 文档：`http://localhost:8000/docs`

启用认证后，第一个注册的用户为 ADMIN，后续注册用户默认为 MEMBER。只有 ADMIN 或 SYSTEM 可以进入管理后台。

## 4. Draft、Published 和 Snapshot

三者语义如下：

```text
Draft
  管理员当前调试配置
  ADMIN/SYSTEM 发起的下一个新任务立即使用

Published
  正式稳定检查点
  MEMBER 发起的新任务使用

AgentRun Snapshot
  任务创建时冻结的实际运行配置
  Draft 或 Published 后续变化不会影响已有任务
```

如果没有 Draft，ADMIN 新任务也会回退到当前 Published。Default Agent 同一时间最多只能有一个 Draft。

## 5. 导入模型配置

### 5.1 支持范围

模型导入层支持 TOML、JSON 和 ENV，并将识别结果转换为现有：

```text
ModelConnection + ModelProfile
```

目前支持的协议为：

- `openai`
- `openai_compatible`

同一协议下新增模型不需要编写模型专用 Adapter。未来只有接入完全不同的原生协议时，才需要增加协议 Adapter。

### 5.2 TOML 示例

进入“模型”页面，点击“导入配置”，粘贴：

```toml
model_provider = "OpenAI"
model = "gpt-5.5"
review_model = "gpt-5.5"
model_reasoning_effort = "xhigh"
disable_response_storage = true
network_access = "enabled"

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://vftsub.vf-tech.cn"
wire_api = "responses"
requires_openai_auth = true

[features]
goals = true
```

点击“识别配置”后，页面会展示：

- Provider 和 Base URL；
- API Mode；
- 主模型及不同的 Review 模型；
- 支持的运行参数；
- 被忽略的非模型字段；
- 自动生成且可修改的名称和 slug。

API Key 必须在预览下方单独填写。即使粘贴内容中包含 `OPENAI_API_KEY`，系统也只识别字段名，不会导入或回显其中的值。

确认“将创建 Provider / Model ID”后点击“确认并保存”。Connection、加密 Secret 和全部 Profile 在同一事务创建，任一步失败都会整体回滚。

### 5.3 JSON 示例

```json
{
  "model_provider": "openai_compatible",
  "model": "customer-model",
  "base_url": "https://models.example.com/v1",
  "api_mode": "responses",
  "parameters": {
    "reasoning_effort": "high",
    "max_output_tokens": 8000,
    "store": false
  }
}
```

### 5.4 ENV 示例

```dotenv
MODEL_PROVIDER=openai_compatible
LLM_MODEL=customer-model
OPENAI_BASE_URL=https://models.example.com/v1
LLM_API_MODE=responses
LLM_REASONING_EFFORT=high
LLM_DISABLE_RESPONSE_STORAGE=true
```

### 5.5 参数和忽略规则

导入层只接受现有模型参数白名单，包括：

- `reasoning_effort`
- `max_output_tokens`
- `timeout_seconds`
- `max_retries`
- `temperature`
- `top_p`
- `enabled`
- `store=false`
- `response_storage_disabled=true`

`network_access`、`windows_wsl_setup_acknowledged`、`features` 等 Codex 或客户端字段不会进入模型运行配置，预览中会列为已忽略。

## 6. 手工管理模型

“模型供应商连接”表示：

```text
Provider + Base URL + API Key Secret
```

“可选模型”表示：

```text
连接 Revision + Model ID + API Mode + 参数
```

连接行最左侧的试管图标用于测试连接。测试会调用模型列表接口；部分代理即使能调用模型，也可能因为没有实现 Models API 而导致测试失败。

当前没有物理删除模型功能。需要下线模型时应先从 Draft 节点解除绑定；后续应采用停用而不是删除 Revision，以保护历史 Published 和 Snapshot。

## 7. 给节点切换模型

1. 确认当前存在 Draft；如果没有，在管理后台创建草稿。
2. 打开“节点配置”。
3. 在目标节点的模型下拉框中选择一个可选模型。
4. 选择会立即更新 Draft，不需要 Publish。
5. 新建 ADMIN 测试任务验证效果。
6. 已有任务继续使用原 Snapshot，MEMBER 仍使用 Published。
7. 测试稳定后再 Publish。

节点来回切换只改变 Draft 绑定，不会创建新的 ModelProfileRevision。

## 8. Prompt 工作稿

1. 打开“Prompt”页面并选择固定节点。
2. 查看当前工作稿和稳定历史 Revision。
3. 点击“编辑工作稿”并保存。
4. 工作稿可以连续保存，不会增加 PromptRevision 数量。
5. ADMIN 新任务立即使用最新工作稿。
6. “丢弃工作稿”会恢复到当前基线 Revision。
7. 也可以选择任意合法历史 Revision 作为新的工作稿基线。

Prompt 保存仍会执行 Placeholder、Skill、节点归属和代码拥有的输出契约校验。非法工作稿不能保存或运行。

## 9. 发布、Diff 和历史恢复

发布前在“版本”页面查看当前 Draft 与 Published 的差异，包括节点 Prompt、模型和固定 Tool Binding。

Publish 会在一个事务中：

1. 完整校验 Draft；
2. 只为真正变化的 Prompt 冻结新 Revision；
3. 冻结模型和 Tool Binding；
4. 写入可选发布备注；
5. 将 Draft 转为不可变 Published；
6. 更新正式版本指针。

发布后不会自动创建下一 Draft。

从历史 Published 恢复时，配置会复制到当前 Draft，不会修改历史版本，也不会立即影响 MEMBER。恢复后的 Draft 经验证后需要再次 Publish 才成为新的正式版本。

## 10. 常见错误

### `AGENT_SECRET_KEY is required`

数据库密钥加密未配置。按照第 2 节生成并配置固定 Fernet 密钥。

### `Model Base URL resolves to a non-global address`

模型域名解析到了内网或 Fake IP。确认域名可信后加入 `AGENT_TRUSTED_MODEL_HOSTS`，然后重新创建 Backend 和 Worker。

### 连接测试返回 404

确认 Base URL 是否需要 `/v1`，并确认代理是否实现模型列表接口。

### 导入提示 slug 已存在

预览阶段修改自动生成的 Connection 或 Profile slug。slug 在当前 Tenant 内必须唯一。

### 新任务没有使用 Draft

确认任务发起人为 ADMIN/SYSTEM，并且是全新任务。MEMBER 始终使用 Published，已有任务始终使用原 Snapshot。
